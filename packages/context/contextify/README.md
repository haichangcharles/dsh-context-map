# @deepseek-ai/dsh-contextify

English | [中文](README.zh.md)

## Summary

`dsh-contextify` turns a connected family of native Harness Session forks into one message-level Context Map and registers the `contextify@3` Context Compiler. It does not create a second branch model: every branch is an ordinary Session whose `parentSession` and `inheritedEventCount` remain owned by Harness.

## Current behavior

On `agent/session-start`, the plugin selects the Contextify compiler and creates a Natural plan when no plan exists. A newly forked child inherits the parent's event prefix but starts with its own Natural plan; context edits are never silently inherited.

The family projector walks from the native root Session through every native descendant; Sessions marked `origin: subagent` are execution details, not chat branches, and are excluded. It de-duplicates copied prefix messages by their earliest owning Session and projects genuine user inputs, native `web_fetch`/`web_search` results, worker reports, and the last visible text/image assistant message after a successful `turn/end`. Each node carries a `chat`, `web`, or `worker` source kind; successful text-only Web results retain the matching native `web_fetch` or `web_search` action only when the result cites its tool call. That action marks the result eligible for cross-branch import. Assistant text stays out of the graph while a Turn is running; earlier ReAct steps, intermediate questions, failed or interrupted partial output, reasoning-only assistant events, tool calls, non-Web tool results, context injections, and other runtime events are intentionally absent. Chat nodes resolve to their enclosing completed `turn/end`, which is the boundary accepted by native Session fork; evidence nodes are not fork pivots.

Each projected Session also has a task work state. Active branches default to `open`, inactive branches to `parked`, and only a reviewed `contextify/work-state` event can mark one `completed`. A later user turn on that branch reopens it. These states are derived from append-only native events and guarded by a family graph revision; they do not alter the Context Plan or next compiled request. The route planner avoids a completed destination for a generic new task while permitting explicit Resume and evidence Include.

The durable plan has three selection modes:

- **Natural** keeps a message when it belongs to the active Session's inherited or local history.
- **Exclude** omits one Natural historical message from the next compilation.
- **Include** copies a message from another Session in the same native family into a local `context/compiler-snapshot` event and inserts it at a stable position.

Plan v3 also supports reversible, per-message **Archive** overlays for a user input or finalized assistant output. Archive is deliberately independent from context selection: the service replaces only the model-visible semantics with the fixed marker `[Placeholder: intentionally empty]`, without accepting Agent- or client-authored replacement text. The same graph node, role, edges, native fork boundary, and original append-only Session event remain intact. Restore removes only the overlay. Reset clears Include, Exclude, and Archive overlays; Undo and Redo replay all three. Existing v2 plans are normalized in memory without writing during reads, and existing v3 replacement snapshots—including older custom text—remain readable and restorable.

Every plan mutation is compare-and-set by revision and records complete undo/redo state. Reset returns to Natural. Cross-family references, unavailable messages, stale revisions, unsupported transitions, and non-idle Agents fail without a partial plan change. Cross-map import is deliberately out of scope. On-path Web and worker evidence can be Excluded, restored to Natural, and recovered with Undo. A same-family, off-path Web result with one matching recorded tool call and successful text-only content can be Included as a logged `recall` snapshot containing the tool name, call arguments, and quoted observation; its snapshot records the original Session and result sequence. Undo removes it from the next compilation. This is a rendered evidence copy, not a replayed tool exchange or a prompt-injection defense. Off-path worker evidence remains unavailable for Include, and evidence cannot be Archived as a conversation placeholder.

When a compaction checkpoint covers a historical message excluded or archived by the active plan, compilation unfolds that checkpoint through its recorded source events and applies the current per-message selection. Other checkpoints remain compact, and Undo can select the original checkpoint again. This applies to recorded message sources, not to unrecorded information read by a summarizer.

Native branch ancestry is canonicalized for navigation. Re-forking from a boundary inherited from a parent produces a sibling of the existing branch; forking from a boundary created inside a branch produces its child. The graph continues to show the real shared message pivot either way.

The `contextify` Remote namespace exposes `get`, paged `familyPage`, `stewardProfile`, review-only `recommend`, `cancelRecommendation`, `presentRecommendation`, `dismissRecommendation`, `reviewRoute`, `recordManualBranch`, `setNodeMode`, batched `setNodeModes`, `archiveNode`, `prepareBranchSuggestion`, `keepBranchSuggestion`, `acceptBranchSuggestion`, `restoreNode`, `reset`, `undo`, and `redo`.

`stewardProfile` projects Client-confirmed Context choices from native Session logs across the same DSH Profile into a compact policy memory. It reports smoothed acceptance rates, support, review thresholds, and repeated-choice rules for Include, Navigate, Branch, Return, and Release. It reads changed Session families and reuses cached projections for unchanged families; inaccessible historical families are skipped with a Host warning. Include/Release observations can retain the selected node's `chat`, `web`, or `worker` source kind, so repeated source-specific behavior need not become a global preference. When an explicitly reviewed objective starts with a clear writing, planning, or brainstorming cue, its feedback is tagged with that task activity; Branch reviews recover the authored input at the reviewed Turn boundary rather than taking a later input. A successful manual Context Map fork records the bounded draft transferred to its child, so the same activity rule can condition this explicit Branch choice; an empty draft stays unclassified. Repeated-choice summaries can expose task-specific or source-by-task exceptions when the broader rule is mixed or points the other way, and omit redundant narrower rules. The current draft's activity selects the matching policy cell after four effective reviews, otherwise it backs off to Profile-wide behavior. Ambiguous objectives stay unclassified. Estimates also condition on nearby branch depth. Reviewed draft-route cards supply explicit Navigate, Return, and Branch choices; a successful manual Context Map fork supplies a positive Branch choice through `contextify/manual-branch`. Merely seeing a route card supplies no preference. One multi-item review has total weight one; passive card presentation, unmarked Remote calls, and undone plan changes do not provide preference evidence. The projection changes suggestions only and does not authorize automatic Context Plan or Session mutation.

When Fast review receives an explicit draft objective, it also runs a conservative, keyless native-Session route policy after the existing classifier. Clear requests to return to the parent, resume a matching prior branch, or start a separate topic may produce an independent review-only route card. Short corrections and ambiguous branch matches abstain. The same Fast model call supplies Include/Exclude advice; the route fallback does not add a second call. The Client rechecks the exact draft, graph revision, Plan revision, and destination before moving it. `reviewRoute` records an explicit acceptance after a successful transfer or an explicit Stay choice, and does not itself switch Sessions. Both route advice and the Fast Include/Exclude residual can use confirmed choices from other Sessions in the same DSH Profile.

An explicit draft command to Ignore/Exclude one exact Web URL takes a cheaper Fast path. Contextify resolves the URL only against a causally bound `web_fetch` call, requires one currently selected result with no conflicting manual Include, and returns a review-only Exclude without calling a model. A URL mentioned only inside fetched page text is not a source identifier. Absent or ambiguous matches use the ordinary Fast reviewer. Apply still checks the graph and Plan revisions; the draft remains unsent and unchanged.

`recommend` has two manually selected modes. Fast is the default: one bounded, tool-free classifier reviews likely included and off-path candidates for the next request. Fast discards model-proposed Archive items even when the model ignores its instruction to leave that list empty. Deep is explicit: Contextify writes the complete tree snapshot to a private temporary file, starts one restricted Harness child with only exact-file Read/Grep and structured-submit tools, and removes the file and child on success, failure, cancellation, or timeout. Deep may return conservative Archive candidates; each requires individual user confirmation. Neither mode appends its prompt, reasoning, or result to the parent Session, and neither mutates context before Apply. The shared validator compares output with the current effective set, filters harmless duplicate/no-op Include or Exclude actions, rejects unknown nodes and contradictory actions, and returns one complete Current → Proposed replacement. Applying that proposal is one compare-and-set plan revision, so Undo restores the previous version as a unit.

In long conversations, Fast also ranks up to eight older included messages on the active path by overlap with the current objective plus a bounded residual from prior confirmed Context choices, while reserving space for off-path candidates. This can surface an older source whose wording differs from the current draft when an earlier reviewed choice links that request to the source; sparse histories keep the lexical fallback. For each high-ranked older message it checks for a later, same-role active message with enough shared terms, so a later correction can enter the same review even when it uses different words from the current objective. After a branch pivot, it additionally keeps up to three messages from the active branch entry visible even if the latest objective shares no words with them; at most six such entries are admitted, without consuming the reserved off-path space. For off-path candidates, Fast first reserves up to four eligible, source-bound Web observations, preferring distinct branches and then filling by score, before the general branch-coverage and score-fill stages. This prevents many lexically similar old chat turns from using every off-path slot while leaving the remaining slots for chat and other candidates. The packet remains capped at 32 nodes, with at most 12 off-path nodes. This gives the reviewer both versions of a possible constraint and the returned branch's original purpose; routing alone never changes the Context Plan.

The Fast packet also shows at most four earlier Client-confirmed Context choices from the current Session family, with each objective and message excerpt capped at 180 Unicode code points. It selects up to two examples related to the current objective and fills remaining slots with recent choices; fractional choices from a reviewed sheet retain their group weight in this bounded list. Up to two accepted, changed multi-node recommendations of at most four choices each are instead kept as grouped `planExamples`. Each choice records whether its message was selected before and after the accepted edit; a batch is omitted unless every selected node actually changes. Incomplete and unmarked batches are also omitted. These are evidence for the classifier, never instructions or new Plan mutations. Source/path style alone no longer adds Exclude suggestions for chat messages: five exclusions of old chat constraints must not automatically remove a later correction with the same broad graph role. A classifier may still propose a specific chat exclusion after seeing both versions; the user must confirm it.

Fast review also uses the latest 32 Client-reviewed Include/Exclude choices across the same DSH Profile, ordered by event time. The Host uses these choices for candidate ranking and proposal calibration; text from other Session families is not copied into the model-visible preference examples. These are changed single-node direct edits, accepted recommendation selections, and explicit Keep-current choices on a confirmed review; a direct `natural` restoration counts as Include on the active path or Exclude off-path, while an unchanged operation counts as neither. Each confirmed review contributes one total observation across its accepted and declined items, including a Keep-current-only review. A bounded residual combines similar objectives and material with a strongly shrunk organization-style term after four same-topology, same-source-kind observations; it reranks eligible off-path chat and call-bound Web candidates before the model call. A source-bound Web candidate's Fast text includes the recorded tool-call arguments and result text, so the router can compare the original Web query with the current objective. Fast routing and the personal residual share normalized word and CJK bigram matching, so comparable Chinese objectives do not collapse to zero lexical overlap. Once five typed path-aware choices exist, a second training-free policy compares source-kind, active-path and joint-cell experts by leave-one-out accuracy on the earlier edits. Web source matching distinguishes `web_search` from `web_fetch` when the native tool action is known; older untyped choices retain the broad `web` fallback. Its Beta-smoothed rate backs off from sparse cells; five unanimous recent full-weight choices in an exact source/action/path cell can also reverse a strong earlier style. After ordinary validation, personalization can suppress a conflicting generic action, add at most two reviewable Exclude suggestions for still-included active-path nodes, or add at most two positive Includes for graph-routed off-path chat or call-bound Web nodes. Already excluded nodes cannot consume these two Exclude slots. Automatic off-path Web Include requires stronger task-term overlap than chat Include, and candidates are ranked by lexical relevance plus the personal residual. It cannot import off-path worker evidence or unbound Web results. The result is validated again. Explicit plan edits remain authoritative, no plan changes before Apply, and there is no extra model call. With no eligible choices, Fast review is unchanged. This policy does not infer intent from inactivity, unreviewed recommendations, whole-sheet dismissal, or batched direct mutations.

The confirmed `contextify/recommendation-reviewed` event retains the bounded objective used for that review, including a draft objective that has not yet become a `user/message`. Personal Context examples use this exact objective instead of pairing the choice with an earlier sent turn. A confirmed `contextify/route-choice` likewise retains its reviewed draft objective. Unreviewed and dismissed proposals do not persist the objective as preference evidence. Older review events without an objective remain readable and use their nearest earlier logged user message as a legacy fallback.

The preference policy also records whether a confirmed Chat source was authored by the user or assistant. It can select a speaker-conditioned habit when the two roles have different Include/Exclude patterns; a strong typed habit takes precedence over a conflicting broad lexical residual. This affects reviewable proposals only. The current Fast candidate router may still omit distant, lexically dissimilar messages, so the policy cannot manage every old source in a long chat.

An Exclude accepted through a Client-declared recommendation review remains in the Plan until another confirmed edit. If the current request needs that source again, Fast marks it `reviewableExcluded` and the classifier may propose Include; the earlier temporary exclusion does not suppress this restoration through the personal preference residual. The validator still protects direct user Excludes and archived replacements. A restoration is only a proposal, and the next model request includes the source only after the user accepts it.

If at least five earlier direct choices in an exact source/action and path cell formed a strong preference, five subsequent independent, unanimous opposite choices in that same cell switch its review advice. Fewer corrections and fractional batch selections do not trigger the switch. This bounded change detector helps a user revise a former habit; it does not automatically edit the Plan or establish a measured personalization benefit.

Each `setNodeModes` call that commits a Plan records a log-only `contextify/node-choice` event after the plan revision. A current reviewed proposal can apply only its accepted items; keeping every item consumes the review without a Plan revision. It records the changed node modes and whether the call applied the current reviewed recommendation or invoked the Remote method directly. A recommendation application also retains the proposed selection; a no-op is marked `changed: false`. The separate `contextify/recommendation-reviewed` event records the exact proposal actions and the accepted and declined node IDs. Fast review uses Client-declared reviewed choices, with declined actions inverted to the explicit current-selection preference. A guarded Apply whose reviewed proposal is unavailable must request a fresh recommendation. When a current review sheet renders in the visible Client document, `contextify/recommendation-presented` records its exact proposal once without changing the Plan or graph revision. This is evidence of a rendered sheet, not attention or acceptance. Explicitly closing a current review sheet records `contextify/recommendation-dismissed` with the exact pending proposal's base and selected actions; it consumes that proposal without editing the Plan. A dismissal can record explicitly toggled Keep-current items but is not used as a preference observation; closing the sheet is not rejection of every proposed action. Cancelling a running review, clearing an error, losing a stale proposal, or doing nothing records no negative choice. The shipped Client marks its calls with `uiOrigin: contextify-client`; an unmarked Remote call remains distinguishable. The marker identifies a Client path, not authenticated human identity.

Automatic Branch review is enabled for fresh Profiles and can be disabled in the Prompt Dashboard. The tool-free classifier starts concurrently from the first human input and is bound to the exact final Q&A only after a successful Turn completes, so the main answer never waits for it. Its bounded packet contains the new input, the current and ancestor objectives, at most three recent local Turns, branch depth/load, and at most four sibling intents—not the complete tree, reasoning, or tool events. A dynamic high-confidence threshold suppresses noisy generic suggestions; malformed, failed, disabled, and stale reviews are silent. The Host calibrates that classifier using up to 32 recent, Client-reviewed Keep/Move choices across the same Profile's native Session families; the older review text stays in the Host policy and is not sent to the classifier. A generic Keep can become a reviewable Move after repeated nearby-depth Moves or similar explicit Moves; a generic Move can be suppressed after repeated nearby-depth Keeps. Strong style paths require repeated reviewed choices and leave extreme-confidence decisions untouched. If historical Profile reads fail, the current family remains available for calibration. The model-facing `request_context_branch` tool remains available when automatic review is disabled: an explicit direct-human request schedules the same post-Turn confirmation card and never claims the branch was already created. Accepting a visible suggestion first uses the Harness Host's native before-Turn fork path to create a complete Agent-backed child at the preceding balanced boundary, then replays the exact Q&A into that child and archives the source input and final output with deterministic placeholders. A bare live Session is rejected, preventing ordinary navigation from racing persistence resume. The relocation has a deterministic key and is idempotent; it is rejected if either conversation advanced or the native child does not match the suggested boundary.

An explicit Keep or successful Move appends one `contextify/branch-choice` event to the source Session, linked to the reviewed suggestion and completed Turn. The shipped Client marks its calls with `uiOrigin: contextify-client`; direct Remote calls remain unmarked unless their caller declares the same origin. Duplicate actions do not create duplicate choices, and a decided suggestion stays hidden after a Client reload. A generated suggestion alone is not a user choice.

Subsequent automatic Branch reviews use the latest 32 Client-declared Keep/Move choices from the Session family, ordered by event time, to calibrate the confidence threshold. The adjustment weights similar input wording and branch depth, treats explicit Keep and Move symmetrically, shrinks toward the generic threshold with little feedback, and is capped at five confidence points in either direction. A Keep raises the threshold; a Move lowers it. At least five nearby-depth reviewed choices can trigger a Beta-smoothed style path: mostly Keeps suppress a non-extreme generic Move, while mostly Moves can surface a reviewable card from a non-extreme generic Keep. Repeated lexically similar Moves provide a separate weak-Keep path. These rules were adjusted on development examples and have no independent accuracy guarantee. Unmarked Remote choices do not train this policy. Personalization changes whether to show a suggestion, never creates a branch without approval, and has no measured accuracy guarantee yet.

All three review agents use Profile-owned settings. Package default prompts remain the read-only baseline; users normally append additional instructions and may explicitly unlock a full override. Context selection guidance applies to Fast, Archive guidance applies to Deep, and Branch guidance applies to post-turn review. Each uses the Harness provider/model path of the parent Agent.

The package also exports an opt-in revision-lineage compiler and append-only delegation-slice/request-read-set helpers for research integrations. `startSourceBoundContinuable` builds a text-only spawned child's delegated prompt from selected human Session messages, native Web tool results, or a selected Contextify Web recall snapshot. It verifies each native Web result's call event and each imported snapshot's provenance, recall form, and content hash, records the selected parent events before startup, and grants no global tools. Removing an imported snapshot from the active Plan invalidates a child delegated from it; a later edit to the original sibling Session is not tracked across Sessions. When using the helpers directly, callers must select the lineage compiler and record each parent request before dispatch, including steps with no newly accepted messages. The compiler rejects stale child messages whose recorded parent sources, including transitive checkpoint sources, are denied by the current plan, and recursively removes historical child messages and parent answers derived from those sources. `guardDelegatedToolCalls` can reject all subsequent tool calls from specified children when their recorded source slice becomes invalid; ToolRuntime rechecks the guard at body entry after async dispatch wrappers. Other plugins can still inject input into the child request: a synthetic workspace-instructions test demonstrates this gap. These helpers do not observe such ambient inputs, scoped tools, or external reads; shipped profiles do not install the opt-in runtime, and the current prototype has no complete source guarantee or commit-time protection for an effect already running. Contextify also rejects an edit while the parent Agent is running, so the prototype does not provide in-flight parent-output revocation.

Mount `@deepseek-ai/dsh-contextify/revision-lineage-runtime` after ContextifyService for a reusable opt-in path. It selects the lineage compiler on a new Contextify Session before its first provider request, filters stale child messages at every pre-step, records each request read set, and keeps at most 64 rejected messages per Session in memory for inspection. A legacy Session with unrecorded assistant history continues on ordinary Contextify; it receives no lineage protection or fabricated read sets. The runtime exposes `list_context_sources`, which pages over at most 16 currently selected, text-only human or Web sources with short previews, and `delegate_context_sources`, which revalidates one to eight selected event sequences before recording a source slice and starting a tool-free spawned child. In a protected Session, ordinary `subagent*` and `send_message` tool calls are rejected because they lack or can change that slice. Legacy Sessions retain those tools. The 30-case native-fork replay and a keyless Loader-composed Web test exercise source-bound children; shipped profiles still use ordinary Contextify selection unless they mount the opt-in runtime.

<a id="model-experience"></a>
## Model Experience

### Compiled Context Plan

#### What the model sees

The ordinary Harness transcript remains append-only. Contextify selects active-family messages in their existing order, removes explicit exclusions, substitutes confirmed placeholder snapshots, reads included sibling messages from durable `context/compiler-snapshot` events, and restores current-turn messages so an old plan cannot hide the request being answered.

#### Token effect

The compiler adds no prompt prose. Exclusion can reduce conversation-history input tokens; sibling inclusion increases them by the selected snapshot content. Unfolding a checkpoint can increase the compiled input beyond the physical Session surface's token estimate; `compaction-basic` measures the physical surface, so its automatic pressure decision does not account for this difference. The opt-in lineage runtime adds two native tool schemas to the model request. Listing sources returns at most 16 previews of 180 Unicode code points each per page; the source-bound child receives the full selected source text in its initial prompt, so delegation can add child input tokens.

#### KV Cache effect

Any earlier change to the selected message prefix can reduce KV-cache reuse from the first changed message onward. Leaving every node Natural preserves the ordinary Session message order. Enabling the lineage runtime or editing a past Plan can change the provider request prefix and reduce cache reuse.


## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- The Web client polls the family at 1.5-second intervals while a surface is subscribed; a dedicated projection event can replace this later.
- Enabled Branch review adds at most one small auxiliary model call per eligible Turn; users who prefer zero background classification can disable it per Profile.
- Cross-map import is deferred; only Sessions connected to the same native root are addressable.
- Contextify placeholders are overlays on existing nodes; unrelated compaction relationships are not expanded into shadow nodes.
- The package remains in this Harness fork while its compiler, Remote, replay, and UI seams stabilize.
- The opt-in source-bound worker constrains its initial delegated text and grants no global tools, but ambient child prompts, direct service calls that append child input, external reads, and effects already started before an edit are not covered by the recorded slice. Quarantined messages are in memory, not a durable user-facing inbox.
