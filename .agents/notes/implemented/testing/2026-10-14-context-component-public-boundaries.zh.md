# Agent Note：Context 组件的公开交互边界

Status: implemented

[English](2026-10-14-context-component-public-boundaries.md) | 中文

## 问题

浏览器验收未覆盖 Context 控件中的所有错误、可见性和异步归属路径。严格覆盖率门禁发现菜单、节点控件、推荐审核、草稿审核、分支建议和提示词设置中仍有未验证的决策。

## 决策

新增独立的[公开组件测试](../../../../packages/client/ui-contextify/tests/component-boundaries.client.spec.tsx)，通过渲染后的 DOM 事件和真实类型化译文验证。菜单测试覆盖指针事件传播、同步失败、原生操作拒绝和准确的节点归属。节点及 Chat 控件保持相同的持久化模式，并隔离画布手势。只有明确的 Keep 操作成功后，分支建议才会消失。

草稿测试覆盖菜单模式、待处理控件、文本变化、失败和卸载。在同一个 React 批次中发送两个排队的原生点击事件，验证待处理保护能够在禁用控件渲染前合并重复审核请求。推荐测试覆盖部分及反向的上下文选择、独立的路由与任务生命周期决策、归档审核、过期方案和可见性重试。设置测试连接公开 scope，验证加载及不可用状态，恢复失败的预算编辑，并保存自定义提示词。

[主面板测试](../../../../packages/client/ui-contextify/tests/context-map-panel.client.spec.tsx)包含 79 项公开边界用例。依赖图的私有回调现在在创建时捕获确定已就绪的图，或由渲染后的控件传入已经收窄的图或画布实例。就绪的策略状态同时发布 profile 和证据。这些构造不变量仅消除冗余的内部回退；仍保留并验证异步框选取消、可空手势锚点、未知节点所有者、画布卸载清理和待处理修改保护。

## 考虑过的替代方案

**直接调用组件的私有回调。** 这会绕过事件边界，并可能构造用户无法到达的状态。

**删除防御性保护或忽略覆盖路径。** 保留现有运行时行为和严格覆盖率门槛。

## 影响

不改变产品行为、图布局、供应商请求、依赖或性能预算。孤立的卡片测试在外部库边界替换 React Flow Handle；现有图测试及浏览器测试仍验证其定位。这些测试证明本地 UI 契约，不证明模型质量或真实用户个性化。[传输边界说明](2026-10-14-context-client-transport-boundaries.zh.md)独立覆盖 controller 和 Client 组装。

## 测试

新测试文件的 27 项测试通过；与四个现有所属测试文件合计 118 项测试通过。八个组件源码和浏览器 Loader 入口的语句、分支、函数、行覆盖率均为 100%：273 个语句、246 条分支路径、132 个函数和 216 行。独立的两项视图 store 测试验证选择去重、取消选择、位置覆盖和清除操作不会重置布局；该 store 的各项覆盖率均为 100%。组件夹具还通过聚焦的 Client TypeScript 验证和 lint。最终完整 Contextify UI 检查的 13 个文件、235 项测试全部通过。覆盖全部 UI 包源码的四项覆盖率均为 100%：1,260 个语句、932 条分支路径、473 个函数和 1,020 行。该汇总证明本地 UI 验收，不表示 Linux、Windows、快照、端到端检查或整个 CI 工作流都已通过。
