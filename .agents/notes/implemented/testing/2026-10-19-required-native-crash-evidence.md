# Agent Note: Required Windows native crash evidence

Status: implemented

English | [中文](2026-10-19-required-native-crash-evidence.zh.md)

## Problem

A required Windows Vitest fork previously exited with access violation `0xC0000005`. Separate bounded diagnostics did not reproduce it. A later passing diagnostic does not fix or replace the failed required verdict. Capture must follow the actual required runner, Node selection, pnpm environment and test invocation.

## Decision

The required native and coverage jobs in [ci.yml](../../../../.github/workflows/ci.yml) call [the Windows wrapper](../../../../scripts/run-windows-native.ps1). Its default native lane preserves the original four files, `pnpm exec`, default reporter, serialization and timeout. The coverage lane runs the original `pnpm run check:ci:coverage` once, retaining partition, worker, reporting and timeout configuration. Each invocation propagates failure. No dependency, runtime flag, assertion or production behavior changes. Coverage also produced an unexpected fork exit without an assertion failure; it is not classified as the earlier access violation without exception evidence.

On disposable GitHub-hosted Windows only, [debugger preparation](../../../../scripts/prepare-native-debugger.ps1) uses the official signed Microsoft SDK and matching public Node symbols. The native lane attaches CDB to the original child tree, installs exception filters before work and preserves the original check result in an exclusive private receipt. Heap warnings fail independently of exit0. Coverage retains [AeDebug](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/enabling-postmortem-debugging) postmortem capture; `.jdinfo` selects the exception context. Logs contain stacks and module inventories, not memory dumps. An independent fatal marker also fails either lane.

The [registry owner](../../../../scripts/native-postmortem-registry.ps1) saves and restores only Debugger/Auto values with their original types and raw values, including case-insensitive names and unexpanded strings. Its `finally` restores settings after success, failure or partial setup. A six-case private HKCU fixture checks normal and throwing callbacks for absent keys, unrelated values and lowercase expanded-string/DWord settings. Self-hosted runners run the original command without debugger setup or machine-registry changes. Model credential variables are blank for both keyless jobs; each lane has its own diagnostic log.

The hosted wrapper also uses [OS process-exit notifications](../../../../scripts/windows-process-exit-evidence.ps1) to report descendants' numeric exit status when no unhandled-exception stack appears. Private CIM subscriptions buffer [process starts](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/krnlprov/win32-processstarttrace) and [stops](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/krnlprov/win32-processstoptrace); OS-time ordering resolves ownership from the wrapper PID and revokes reused PIDs. Logs contain process names, IDs, times and exit status, without arguments, environment or dumps. The summary is explicitly best-effort: late/missing notifications can omit exits, decoding is capped at50000notifications, and32nonzero details retain omission counts. Expected nonzero child exits do not fail a passing command. Setup/collection failures warn, the original callback still runs once, and private subscriptions/events are cleaned up on every path. Pure fixtures check ownership, ordering, reuse, bounds and callback failure propagation after partial observer setup. Actual CIM delivery is a Windows CI observation, not proved by those fixtures.

Normal CI retains the original required capture and does not automatically repeat completed reduction experiments. A separately scoped diagnosis on a disposable hosted runner can invoke the [bounded reduction](../../../../scripts/run-windows-worker-reduction.ps1), which executes four fixed return42/result/dispose cycles through the source workflow engine under Microsoft [full PageHeap](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/gflags-and-pageheap). It copies the installed Node binary into the private temporary root under a unique diagnostic image name, requires that image's registry key to be absent, verifies full traces and restores absence in finally. It never enables PageHeap for shared node.exe or a local machine. The [registry fixture](../../../../scripts/native-pageheap-image.ps1) checks success, setup/run/disable failure and collision without a target or machine settings. The probe retains the source worker bootstrap and native disposal, logs identity and lifecycle stages, and never starts a child Agent or calls a model. Each debugger process is limited to150seconds; the target watchdog is120seconds and JS oldspace512MiB, with additional PageHeap memory overhead. Timeout attempts owned-tree termination and a bounded root join, but descendant quiescence remains unconfirmed and blocks further target work. The original native verdict is never replaced; logs and blocked states are retained for three days. Earlier source/built/plain and loader-registration controls remain in their committed revisions and are not repeated. Receipt0 never overrides a raw heap-corruption warning, VERIFIER STOP or unhandled native fault. Diagnostic success is not a runtime repair.

The failure-only hosted timeout control selects `dual-tsx-vm-timeout` in the same wrapper. It uses the installed Node image without PageHeap or registry writes, registers the installed tsx ESM/CJS hooks and evaluates the same immediate async42 program with `runInContext` timeout5000. Four worker/result/termination cycles observe creation and cleanup of synchronous timeout monitoring; they do not trigger a timeout or test asynchronous interruption. Normal CI does not repeat this completed control; separately admitted diagnoses use the retained wrapper. A skipped step is not a negative result. The original required failure remains authoritative, and completed controls are retired rather than repeated on unrelated pushes.

## Alternatives considered

Retrying until green or changing Node/JIT/termination without a fault stack would obscure the cause. Attaching a debugger changes timing; live native capture supplies thread-exit heap evidence that the postmortem coverage path can miss. SDK/symbol availability and full PageHeap memory overhead add diagnostic cost. Small negative reductions do not rule out the original multi-case or compiler/teardown interaction.

## Consequences

This is observability, not a claimed runtime repair. The original failure remains recorded. Native execution of the wrapper must be checked by the required CI itself; fixture and diagnostic passes cannot substitute for that result. No model API, training or paid workflow is authorized.
