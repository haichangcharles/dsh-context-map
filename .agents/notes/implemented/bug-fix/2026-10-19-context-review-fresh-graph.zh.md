# Agent Note：Context 审核前刷新原生 family

Status: implemented

[English](2026-10-19-context-review-fresh-graph.md) | 中文

## Problem

[Client controller](../../../../packages/client/ui-contextify/src/client/controller.ts) 在两次轮询之间保留已加载的图。原生 fork、标题更新或工作区归档可能在下次轮询前改变 family 修订。手动审核发送保留的旧修订，Host 因而在提出 Context 或 Branch 变化之前拒绝请求。后续读取失败时，旧图也会继续展示；保留展示不代表可以安全发起审核。

## Decision

手动 Local、Fast 和 Deep 审核在发出请求前刷新原生 family 与 Plan。Plan 修改尚未完成或读取失败时，审核会被拒绝。既有的瞬态请求计数器同时拥有读取准备与分类结果：清除草稿或提出更新的审核会在传输调用之前使旧准备请求失效。最新等待请求拥有其目标与模式。审核器开始运行后，重叠请求仍会被拒绝。在读取期间获得所有权的修改也会阻止请求发出。

读取之后发生的并发变化仍由 Host 修订校验负责拒绝。这是一次新的元数据读取，不是模型重试、自动模式升级或缓存回答回退。Deep 取消仍针对已经发出的审核；读取期间的清除在本地使尚未发出的请求失效。

## Alternatives considered

等待轮询计时器或重试 Host 拒绝会增加时序依赖或模型尝试。放宽图修订校验会接纳不一致的 family 输入。新增独立准备状态会重复既有请求计数器的所有权。只刷新而不捕获计数器，则被清除的草稿可能在读取完成后重新出现。

## Consequences

手动审核增加一次可去重的图读取，读取失败时可以保留旧地图并报告错误。其他操作引起的变化无需等待下一次轮询便可用于审核。固定同名标题的 Loader 回放覆盖父会话归档后立即审核、确认、Undo 和重载；单元竞态覆盖读取失败、清除、并发请求与未完成修改。工程 fixture 验证执行行为，不代表新的模型准确率或偏好收益。
