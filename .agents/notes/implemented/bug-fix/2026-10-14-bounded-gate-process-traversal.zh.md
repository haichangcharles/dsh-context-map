# Agent Note：有界的门禁进程表遍历

Status: implemented

[English](2026-10-14-bounded-gate-process-traversal.md) | 中文

## Problem

Windows Node 24 CI 在门禁协调器的 `collectDescendants` 中抛出 `RangeError: Maximum call stack size exceeded`，并未正常返回测试或覆盖率结果。原遍历把根的邻接数组直接当作队列，并不断把子列表展开传给 `Array.push`。回指根的边因而可能把持续增长的队列追加到自身；一个普通但足够宽的子列表也会独立超过引擎的调用参数上限。重复或成环的进程表关系同样缺少访问次数上界。失败时的 CIM 表未被保存，因此无法确认 PID 复用就是该次触发原因。

## Decision

[协调器](../../../../scripts/run-gates.ts) 使用独立的广度优先队列。根在开始时即被标记为已访问，每个 PID 在入队前标记，子节点逐一追加。每个可达的观测 PID 只出现一次，保持按进程表首次发现的顺序；根和不连通项不进入结果。遍历不再修改邻接表。队列大小受观测到的唯一 PID 数量限制，遍历工作量与表大小呈线性关系。

同步终止前捕获与异步采样共用该函数。观测到的 PID 值、已缓存后代的保留及合并、信号升级、taskkill 顺序、静止确认与截止时间保持不变。修复不增加操作系统查询、模型调用、重试或覆盖率例外。

## Alternatives considered

- **捕获 RangeError 后返回空后代列表。** 这会掩盖收容失败，并可能遗留所属进程。
- **截断队列或延长门禁超时。** 都不能解决图遍历或参数上限缺陷；截断还可能漏掉后代。
- **只过滤自父节点。** 更长的环、重复路径和宽的无环进程树仍需有界遍历。

## Consequences

把非原子采集的进程表视为观测到的图，而不再假定它总是干净的树。协调器仍无法恢复该快照中不存在的关系；既有保留机制继续处理此前已观测到的后代。[并行门禁决策](../process/2026-07-06-parallel-pre-push-gates.zh.md)继续负责协调策略，本说明不取代它。

## Testing

两个公开输入负对照复现原展开调用处完全相同的 RangeError：根自环和 200,000 个普通孙节点。修复后五个回归用例通过，覆盖根回边、后代环、重复行、不连通项、空输入、输入不变以及广度优先的 taskkill 目标。负责的脚本完整测试全部 96 项通过，包括真实取消、重挂父节点的后代与清理场景。五个新用例在 Node 24 下也通过。定向 TypeScript、lint 和 diff 检查通过。这些本地结果不代表失败的 Windows CI 此后已通过。
