# Agent Note：程序移动 Map 时保留节点操作

状态：已实现

[English](2026-10-14-context-map-move-ownership.md) | 中文

## 问题

搜索会先把消息标记为 focused，再启动延迟的视口缩放动画。初始取景也会等测量就绪后延迟执行。用户可能在这个间隔打开节点菜单。[面板](../../../../packages/client/ui-contextify/src/client/ContextMapPanel.tsx) 原先在 React Flow 的每次 `onMoveStart` 中关闭菜单，包括程序移动产生的空事件，因此随后启动的缩放会把可操作菜单从 DOM 移除。托管浏览器用例观察到 Branch 操作被移除和 Restore automatic 操作缺失；相同的完整用例在本地通过，符合时序敏感行为。

## 决策

程序移动没有指针事件，因此保留已打开的菜单。真实用户移动仍会关闭它。画布指针捕获、空白处点击、Escape 和完成操作保留既有的关闭行为。视口时序、搜索、节点选择、上下文修改和原生分支均不改变。

右侧栏夹具则在关闭自动打开的 Map 后，单独等待 frame 的真实网格动画完成。collapsed 标记和展开按钮会在过渡结束前反映状态；在不同过渡帧读取两个 bounding box，可能颠倒原本要求的先后位置。此就绪屏障发生在原有精确几何断言之前，不引入固定延迟、强制点击、放宽阈值或新 golden。

## 考虑过的替代方案

**等视口移动结束后才允许菜单交互。** 这会引入新的交互限制，且无法修复用户在已排定的缩放启动前打开菜单时的归属错误。

**取消全部移动关闭行为。** 这会让菜单在真实用户平移时仍保持打开。既有指针关闭行为仍须保留。

**放宽几何断言或增加固定等待。** 这只会掩盖中间布局读取，不能证明真实动画已经完成。

## 结果

菜单生命周期跟随用户输入，而非程序取景。不增加新的状态 owner 或事件订阅。侧栏夹具读取稳定布局，同时保留产品默认打开 Map、动画与原有布局约定。即使浏览器调度没有复现该问题，确定性的回调回归也能覆盖这一顺序。

## 测试与限制

既有的公开画布回调用例在右键后触发空移动事件时失败：菜单已不存在。现在菜单会跨过该事件保留，用例仍验证随后真实指针移动、空白处点击和 Escape 会关闭菜单。全部 79 个面板测试通过。面板的 378 条语句、329 个分支、155 个函数和 301 行仍达到 100% 覆盖率；范围内 lint 通过。

修改前，三个所属浏览器文件在确切的现有构建上通过全部 17 个用例。这不能证明托管竞态不存在。补丁仍须经过新构建的浏览器验证；没有修改任何已录制的模型响应或预期产品几何。
