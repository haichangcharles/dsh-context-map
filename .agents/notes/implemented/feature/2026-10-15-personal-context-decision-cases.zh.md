# Agent Note：个人 Context 决策案例

Status: implemented

[English](2026-10-15-personal-context-decision-cases.md) | 中文

## 问题

Profile 范围的选择统计不能说明哪一个早期任务支持当前选择。只对候选排序做个性化，也不能证明最终 Context 或分支操作更好。跨项目的聊天排除通常描述具体任务，将其直接作为全局风格规则可能产生错误迁移。

## 决策

[Contextify](../../../../packages/context/contextify/README.zh.md) 在同一 Profile 的原生 Session 家族间，复用有界的、已确认的目标与选择案例，以及完整、实际改变状态的多节点 Plan 案例。所属事件标识保留撤销与重置语义。候选准入不依赖个性化。跨家族聊天编辑提供给决策模型；确定性校准保留当前家族编辑和带类型的 Web 来源习惯。服务从原生日志派生这些视图，不维护第二份 persona 存储。

Fast 支持 Host 侧 Jev 结构化推理适配器，并保留当前聊天模型路径。任务自有的入口原文、与草稿相关的原文和最近原文形成有界任务卡，不依赖逐节点选材候选；口头填充词标题和缺失的选材候选不能定义任务。独立的任务匹配和明确新任务判断通过原生父任务 Choice、置信度阈值和竞争差值组合。证据和替代关系仍独立判断。明确的完整任务及祖先保留策略采用原生成员关系，普通选材仍默认使用来源相关性。仅 Host 保留的范围来源信息防止被拒绝或覆盖的目标修改当前任务 Context。历史路由案例保留审核目标、带正负含义的选择，以及操作前的有界来源任务、目标和选定父任务文本；其他 Session 同一时间戳的消息被省略。适配器交由原生校验和修订检查处理，发出请求前记录不含凭据的准确内容，只执行一次可取消请求，不重试或回退。图／编译器和 Web Client 不调用提供方 HTTP 接口。[Jev 官方重排示例](https://docs.typesafe.ai/cookbooks/rerank_typesafe) 支持独立查询与候选判断并通过代码组合；这一应用没有提出新的重排模型。

审核表区分模型可见案例与本地校准、路由阈值可参考的有界来源记录。接受与拒绝的选择保留各自方向。设置变化会取消运行中的 Context 和 Branch 检查；策略重置会取消二者，并用所属事件水位过滤旧证据。历史案例文本只用于管理，不进入回答 Context。

每个来源判断单独接收所需原文；提供方的问题彼此独立，无法读取另一个问题的原文。共享状态保留任务元数据和已确认案例。完整任务范围按原生归属和祖先关系编译，也包含分叉后新增的父任务消息和模型候选以外的来源。这是确定性的策略编译，没有授权模型选择未见过的 ID。人工 Plan 约束与目标批准仍具有最高优先级。

## 考虑过的替代方案

**只对候选集合个性化。** 不采用，因为相同检索覆盖仍可能产生不同的无效选材或错误分支目的地，改变候选也会混淆针对决策的对照。

**把每次跨项目聊天选择作为全局统计规则。** 不采用，因为早期针对任务的排除不授权排除新约束。有界任务案例让 reviewer 仍能判断当前目标。

**另加记忆数据库或智能体运行时。** 不采用，因为原生日志已经拥有反馈、撤销、重置和来源。案例检索与可替换推理适配器不需要额外循环或模型微调。

## 结果与影响

用户可选择 Fast 决策模型，并检查支持建议的历史选择。原有人工审核与原生执行约束仍然生效。Jev 需要独立 Host 凭据，也可能因提供方限制而失败；失败不会改变当前 Plan。这项工程接线不能直接证明真实用户偏好收益、回答质量或外部长对话上的统计提升。
