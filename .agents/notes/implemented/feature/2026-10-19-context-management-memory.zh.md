# Agent Note: 带条件的 Context 管理记忆

Status: implemented

English | [中文](2026-10-19-context-management-memory.md)

## Problem

少量独立的历史选择不能表达重复的管理序列。Profile 全局总结也可能把规划任务中的选择推广为全局偏好。单独存储 persona 会重复原生事件的所有权，并使 Undo 与重置更复杂。

## Decision

[Contextify](../../../../packages/context/contextify/README.zh.md)从已有、具有所属事件的策略观察中派生条件规则，以及重复出现的两步或三步工作流。它向 Host 决策数据包、目标审核模型与可检查的建议提供同一个冻结投影。所有模型可见内容沿用现有请求日志；历史案例不进入回答 Context。既有原生操作 DAG 与批准检查仍是唯一执行权威。不引入额外记忆存储、推理调用或 agent loop（智能体循环）。

规则复用先验平滑的支持度，并保留已知任务活动、来源条件和精确起始分支深度。最近八十条具有所属事件的观察最多生成八条规则和四个工作流。工作流要求同一 Session 内所属事件游标递增，或前一步的操作目标等于下一条记录所属 Session 且事件时间严格更晚。Undo 与被拒绝的末步操作会中断序列；支持度混合或不足时弃权。每项保留带正负符号的有效支持度、最多六条原生引用，以及最多两个由有界任务文本组成的工作流案例。完整投影通过丢弃整项来满足 16KiB UTF-8 限制，绝不截断事件标识。Profile 重置与关闭个性化通过现有 Host 所有权移除对应证据。

这一设计借鉴 [ACE](https://arxiv.org/abs/2510.04618) 中有来源的增量上下文规则，以及 [Agent Workflow Memory](https://arxiv.org/abs/2409.07429) 中可复用的操作序列。借鉴范围是组织原则，不包含它们的反思推理、训练、执行器或报告结果。[PenguinHarness](https://github.com/Prism-Shadow/PenguinHarness)提供了这些技术的有用对照；本实现没有复制或安装外部代码。

## Alternatives considered

**无条件和证据的全局偏好文本。** 拒绝，因为特定任务中的选择必须可检查、可撤销，不能意味着当前操作权限。

**持久化第二份 persona 或自动执行检索到的工作流。** 拒绝，因为原生日志已经拥有偏好证据，而历史序列不能确定当前合法步骤或同意。

**从每条 Agent 建议学习，或拼接时间相邻的跨 Session 记录。** 拒绝，因为未确认的建议不是偏好，仅时间接近不能证明属于同一个工作流。

## Consequences

当前模型可以接收有界、可复用的管理证据，无需额外调用。Web 审核单展示同样的条件、带正负符号的支持度和原生引用。单元回归覆盖因果连接、撤销、条件与完整 UTF-8 限制；真实 Loader 组合通过产品服务和工程 provider fixture（测试前置数据）检查模型与建议快照的一致性，以及关闭和重置路径。这些检查证明产品行为，不证明用户建模、模型决策或回答质量提升。跨 Session 事件时间戳相同时会被省略，不人为发明先后顺序。
