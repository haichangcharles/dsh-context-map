# Agent Note: Personal Context calibration

Status: implemented

English | [中文](2026-10-09-personal-context-calibration.zh.md)

## Problem

The Context Map has explicit Include/Exclude and Keep/Move actions, but earlier reviews applied the same candidate ranking and Branch threshold to every Session family. Repeating a rejected Branch suggestion or omitting material like a prior direct Include creates avoidable user work. Existing logs contain too few genuine UI choices to measure effectiveness yet.

## Decision

Branch review joins Client-declared Keep/Move events to their persisted suggestion, counts each owning Session event once, retains the latest 32 by event time, and adjusts the generic suggestion threshold by at most five confidence points. Explicit Keep and Move now contribute equal and opposite signed updates, avoiding the weak positive update from subtracting a high model confidence after an accepted Move. A two-example prior limits sparse feedback; candidate wording and branch depth weight prior choices. After at least five reviewed choices within one branch-depth level, a Beta-smoothed style rate can suppress a non-extreme generic Move when Keeps dominate, or surface a reviewable Move card from a non-extreme generic Keep when Moves dominate. A separate lexically similar-Move path handles weak generic Keeps. All relocation still requires approval. The user still authorizes relocation, and suggestions are not accuracy evidence.

Fast Context recommendation uses the latest 32 Client-reviewed Include/Exclude choices ordered by event time: changed single-node direct edits and accepted recommendation selections. A changed direct `natural` restoration is interpreted by its graph position: active-path restoration is positive Include feedback and off-path restoration is negative Exclude feedback. An unchanged direct operation remains unobserved. An accepted batch has total weight one across its selected nodes, even if applying it made no plan change. Each choice is paired with the latest earlier user message as an approximate objective, the edited node's stable graph preview, and whether the node was on that Session's path. Fast routing and the personal residual share normalized word and CJK bigram matching; continuous Chinese sentences therefore retain local lexical overlap. A local lexical residual and a same-topology organization-style term activated after four weighted observations are shrunk by two examples and capped at 0.2. They rerank off-path candidates before the bounded model review. After ordinary validation, they suppress strongly opposed Include/Exclude actions and may add at most two positive Includes from graph-routed off-path candidates with lexical relevance or a matching earlier Include; the validator checks the proposal again. Explicit overrides remain mandatory. Deep recommendation is unchanged. Neither policy makes an additional model call.

A later sparse-feedback audit found that requiring four observations inside each source-kind/path cell left a ten-edit simulated user with no effective adaptation. Fast review now also selects among source-kind, active-path, and joint-cell experts using leave-one-out accuracy on at least five typed choices. A Beta-smoothed rate with at least three weighted matching observations can veto an opposed generic action or propose at most two active-path Excludes for review. Importable off-path Web results can also receive a bounded Include suggestion through the [source-bound Web import decision](2026-10-10-source-bound-web-import.md); worker evidence cannot. The existing graph validator and user confirmation remain in force. On the exposed simulated cards, the pre-change product calibration matched the generic 9/20 under either of two assumed path mappings; the new calibration reaches 12/20 when every optional source is treated as off-path and 17/20 only when the card's researcher-provided `resume` label is *assumed* to mean active-path membership. Neither mapping is an observed native Session graph, and these are development diagnostics rather than held-out product scores.

The graph records native Web observations and worker reports as typed evidence. Eligible Web nodes retain whether the matching tool call was `web_search` or `web_fetch`; confirmed choices and recommendation packets preserve that action. The source and joint preference experts distinguish these actions when present, while older untyped Web choices keep the broader `web` fallback. Active-path evidence can be Excluded, and source-bound sibling Web evidence can be Included as a recorded recall snapshot; off-path worker import and evidence Archive remain unavailable. This prevents repeated search-result exclusions from becoming a blanket preference to discard fetched pages or chat history. Source-bound delegation accepts a native Web result only when its recorded predecessor is the matching Web tool call. Its source claim remains conditional on the absence of unrecorded ambient inputs and external reads.

`uiOrigin` is declared by the Client and can be spoofed by another Remote caller; it is not proof of human identity or suggestion exposure. The node objective is inferred from the Session log, not recorded at edit time. A no-op or batched direct edit and a generated but undecided suggestion are not training examples. An accepted recommendation is an explicit reviewed choice, but not proof of exposure or user satisfaction.

## Alternatives considered

- **Train a reranker or LoRA now** — deferred because the available logs have no sufficient direct choice labels and a trained model would add cost without a trustworthy target.
- **Feed all history into a personalization prompt** — rejected for this first implementation because it increases context and blurs which edit changed the decision.
- **Use an unbounded user-specific threshold** — rejected because one mistaken click could silence or flood future Branch suggestions.

## Consequences

The shipped behavior has two bounded, training-free adaptation points that can be evaluated against generic baselines with identical model calls. Focused tests demonstrate threshold suppression, a confirmation card after repeated similar Moves despite a weak generic Keep, retrieval of a formerly truncated off-path candidate, filtering of a conflicting Context recommendation, a graph-routed Include suggestion, and recovery of a Web tool action from a native reviewed choice. They are controlled fixtures, not evidence of improved human outcomes. A separate held-out AI-user feature audit, with constructed `resume/new` mapped onto native active-path membership, changed the source-habit role from ten abstentions to 10/10 predictions when Web tool actions were retained; the path-habit role remained 10/10. This tests information preservation, not product task success: the relation mapping is hypothetical, the tested cards are not native Plan executions, and a simple conditional table ties the method. The paper needs executable Session choices and Web outcomes before claiming personalization gain.

A later native Session replay exposed two Fast routing failures: recommendation text omitted Web tool-result bodies, and sorting personalized additions by preference alone could prioritize unrelated branches. Source-bound Web candidates now include call arguments and observation text; automatic off-path Web Include requires stronger lexical task overlap than chat Include, and additions are ranked by lexical relevance plus the personal residual. The replay's 20 AI-user cases became development data because these changes were chosen after inspecting them. With an empty mock generic recommendation, native proposal acceptance and compilation match all 20 simulated optional-source choices, including three Web recall snapshots; this is an execution check, not an independent effectiveness estimate. A separate untouched task set and downstream Web outcome remain necessary for the paper.
