# Agent Note: Complete Context policy approval evidence

Status: implemented

English | [中文](2026-10-20-complete-context-policy-evidence.zh.md)

## Problem

Accepting individual Context edits does not identify a preference for complete task-owned or task-lineage preservation. A route approval can move only the draft. A parsed model policy is not user confirmation, and an existing Client can ignore newly added display fields while still submitting an ordinary approval.

## Decision

[Contextify](../../../../packages/context/contextify/README.md) attaches an optional server-built preservation descriptor to the final pending proposal. It recomputes the canonical native base after Jev: borrowed or removed source exceptions cannot acquire a pure policy label. Empty scopes, unavailable ancestry, replacements, or equal owned/lineage sets omit the descriptor. The descriptor retains the original assignment and task or new-task parent through carried Context.

A server-owned publication identity binds its display key to the exact pending review, original revisions and complete source set. The Client displays the mode and echoes only this key on an explicit full Apply or full Carry. Missing, wrong or old keys retain ordinary action behavior but produce no new policy label. The key supplies no authority and proves neither human identity nor attention. Route-only approval, partial Keep choices, unmarked calls, disabled personalization and unchanged Plans remain unlabeled.

After existing revision, manual and source checks, the Host compares the actually applied native set with the complete proposed set. A matching changed approval annotates the existing reviewed-selection event. No separate memory store or operation owner is created. Its adjacent owned node-choice and native Plan state provide Undo/Redo provenance; existing Profile watermarks remove pre-reset evidence. Inherited copies, malformed receipts and ambiguous legacy history add no examples.

Enabled Host action/goal packets and inspectable decision snapshots carry at most four complete-policy examples, each with its owning Session/event, time, mode, assignment and objective bounded to 200 Unicode code points. Current explicit retention instructions take precedence. Only clearly applicable prior objectives may support complete preservation; conflicting or unidentifiable applicability requires abstention, and one acceptance is not a general preference. Missing or empty example lists preserve the ordinary goal request. Historical assignments do not authorize current destinations or enter answer Context. Existing ranker bonuses, thresholds, routing defaults and inference counts remain unchanged.

The existing Profile inspector exposes this same bounded projection through optional `ContextStewardProfile.scopePolicyExamples`. Its panel shows historical modes, objectives and event references without another RPC or raw-message lookup. Disabled reuse does not erase inspectable history; Undo/Redo and reset update both views.

## Alternatives considered

**Infer policies from partial masks.** Rejected because exceptions, equal source sets and manual constraints make the interpretation non-identifiable.

**Trust a proposal descriptor or Client origin without a display acknowledgement.** Rejected because older Clients can accept the same source set without displaying the new mode. A key without a publication identity also lets an old sheet label a new objective.

**Create a second persona store or learn from no-op approvals.** Rejected because native events already own the evidence, and unchanged scopes lack the same undoable Plan change used by this projection.

## Consequences

The product can retain identifiable complete-scope choices separately from partial edit examples. Engineering fixtures verify legacy compatibility, exceptions, exact pending identity, complete native scope, Carry, bounded model input, Undo/Redo, reset and disable. These establish the learning-input path, not authentic user-model accuracy, automatic Branch quality or model/answer improvements. New-task empty and unchanged scopes remain outside this projection.
