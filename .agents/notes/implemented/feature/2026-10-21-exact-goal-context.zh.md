# Agent Note: 从已校验目标确定完整任务 Context

Status: implemented

[English](2026-10-21-exact-goal-context.md) | 中文

## 问题

完整任务保留请求与逐条相关性审核的用途不同。[目标加 Jev 决策模型](2026-10-18-goal-context-composition.zh.md) 在原生保留基础范围之上允许来源例外。希望准确保留基础范围的用户需要独立选项，而不依赖第二个模型保留每个成员。

## 决策

可选 `goal-model-native` Fast 决策模型使用既有目标请求和已校验类别归属，再复用原生归属／祖先解析器、路由规划器和 Context 编译器。它至多调用一次聊天模型，不解析 Jev 凭据，也不调用 Jev。单位路由值编码类别，不是模型置信度。默认决策模型及既有 Goal+Jev 来源例外语义不变。

仅完整任务自有或任务加祖先策略可继续。Unknown 或相关性策略、无法核验的来源以及已识别的逐条来源例外均弃权。自然语言例外识别仍依赖模型；若误分类为任务自有，仍会保留该完整基础范围。新任务自有分支从空历史开始，父节点仅决定放置。其他目标需要路由规划器接受的同一精确草稿。缺失、空白或截断草稿不能授权没有对应 Branch 的新任务范围。

Host 将最初完整基础范围独立于后续规划保留。发布前检查最终集合、不可用目标及选中来源的替换。手动选择或路由冲突不能静默放宽完整范围。批准、取消、过期状态校验和既有 Undo／重置证据仍具有权威性。不增加事件、记忆存储、模型提供方、权限或偏好权重。

此方法借鉴 [SOM-DST](https://aclanthology.org/2020.acl-main.53/) 的先决定操作再更新状态的分解方式，不使用其神经跟踪器，也不宣称复现。实际复用实现是既有原生产品服务。

既有八候选上限省略其他原生任务时，共享目标输入会披露大于零的省略任务数。两种目标决策模型均收到部分清单提示。既有候选及合法 ID 不变；这不会找回省略目标，也不能认证模型会正确弃权。旧数据包没有数量字段，不代表全局完整。

## 考虑过的替代方案

**限制既有 Jev 输出。** 来源例外是受支持行为，且没有确定性校验器能认证自然语言例外意图，因此不采用。

**依赖更强的逐来源提示词。** 提示词不能保证完整集合，原生编译器已有确定性成员管理能力，因此不采用。

**修改默认值或绕过批准。** 类别式任务归属仍可能出错，完整保留是用户主动选择的策略，因此不采用。

## 影响

受支持检查无需第二次辅助请求，且完整基础范围不受评分候选限制。代价是此模式不支持细粒度借用和排除；不确定或冲突情形需要其他决策模型或手动管理。这些是范围与调用次数保证，不是已测量的语义 Branch／Return 准确率、延迟、金额、回答质量或真实个性化收益。检查面板与历史证明规则不变。
