# Agent Note: 逐条例外之前的明确 Context 保留策略

Status: implemented

[English](2026-10-20-explicit-context-retention.md) | 中文

## 问题

任务目标不决定需要保留多少历史。独立相关性分数可能在明确保留要求下删除不相关材料，新任务父节点也可能错误带入 Natural 历史。有界候选无法描述完整的大任务范围。

## 决策

既有可选 goal 请求返回互斥的 relevance、task-owned、task-lineage 或 unknown 保留策略。这里借鉴 [SOM-DST](https://arxiv.org/abs/1911.03906) 先操作、后值的分解方式，不复现其神经实现或基准。DSH 仍拥有循环，原生 Session/Plan 拥有持久状态，不增加推理调用或 persona 存储。

Host 从同次冻结的家族 inspection 计算保留范围。自有来源必须属于 owner 经核验的非继承事件后缀。祖先沿完整不可变父记录链，而非可能在继承边界折叠的显示父节点。必需来源缺失或成环时，在 Jev 前弃权。新任务自有模式的历史基础为空，父节点只决定放置。

保留模式的候选问题判断显式请求例外之后的最终成员关系。低回答相关性本身不能删除基础材料，相关性本身也不构成范围外借用要求。未询问的基础来源继续保留。包括已审核例外的完整选择集同时用于活动 Continue 与路由范围。显式路由与已分配目标或 new/existing 类别冲突时，整个自动组合提案弃权。原生校验仍保护手动选择、替换检查、取消、图修订和显式确认；无关统计校准不能改变保留提案。相关片段模式保持逐条检查，独立 Jev 保持单独的 wholeTask 语义。

部分历史编辑与 owner 关系不能识别完整保留偏好。类别请求将它们作为证据，而非完整 mask。既有确认操作投影、Undo、关闭和重置仍有权威性。新 goal 输出必须含保留字段，保存的历史模型记录不重新解码或迁移。

## 考虑过的替代方案

**在 wholeTask 旁增加独立的自有范围分数。** 拒绝，因为两者同时高分会留下策略歧义。

**只用逐条排序或有界候选 mask。** 拒绝，因为两者都不能保留完整任务中未询问的来源；允许生成来源 ID 还会绕过原生权威。

**另建保留策略 agent。** 拒绝，因为现有 goal 请求可表达类别操作，不需另一循环、owner 或模型调用。

## 后果

已知目标的请求发生变化，新请求的真实模型质量仍未测量。原生 fixture 覆盖超过32来源的完整范围、Continue/Return/新任务组合、原始祖先、显式借用与排除以及 Undo。这些是工程验收，不是真实用户偏好学习或真实数据联合准确率提升。可选 reviewer 和全部默认值沿用现有部署策略。
