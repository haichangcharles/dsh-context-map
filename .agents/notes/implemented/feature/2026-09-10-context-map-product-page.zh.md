# Agent Note: Context Map 产品首页

Status: implemented

[English](2026-09-10-context-map-product-page.md) | 中文

## 问题

Fork 的 GitHub Pages 首页展示上游文档，而非 Context Map 产品。访客需要简洁介绍、简短易懂的上下文选择演示和源码安装入口。

## 决策

产品首页的静态 HTML、CSS 和浏览器 JavaScript 位于 `product-site/public`。暗色版式参考 Linear 与 Zed，采用近黑中性背景、清晰文字、低对比边框和克制的绿色点缀，文案独立制作。默认英文，支持由 URL 保存的中文切换。固定高度的展示窗替代纵向展开的截图导览。四个始终可见的标签覆盖分支、上下文、审阅与恢复、提示词，默认选中分支。详细说明及分支菜单、归档截图通过折叠详情查看。标签支持方向键、Home/End 与手机横向滑动，不自动播放。小屏幕上的分支截图聚焦地图区域，原图链接保留完整截图。画面来自运行中的应用；会话和审阅建议明确标注为预设示例，不冒充实时 AI 结果。

`product-site/capture.config.ts` 与 `apps/web/tests/product-walkthrough.capture.ts` 通过隔离 Web 脚手架复现截图。用例验证原生分叉关系、跨分支消息进入真实上下文编译结果、排除消息但保留历史、审阅阶段不修改上下文、应用与撤销，以及归档与恢复。它与其他使用脚手架的 Web 测试一样，归属宿主端 TypeScript 检查。

构建将产品首页覆盖到文档产物中，保留文档路由。Fork 专用 Pages 工作流从 master 发布组合产物。上游手动文档工作流不在本 fork 部署，防止后续文档发布覆盖产品首页。两个工作流保留相同的 Pages 并发组。

## 考虑的替代方案

用独立落地页部署替换文档会破坏已有指南地址。将宣传页放入 Agent Web 应用会让公开静态介绍依赖私有会话与运行时设施。复制其他品牌的素材或宣传主张会误导访客对本社区项目的理解。

## 后果

首页无需凭据或运行时即可由 GitHub Pages 托管。源码安装及旧会话迁移限制保持可见。发布仍然构建文档，并使用已有 Pages 环境策略，不移除保护。

## 验证

验证桌面和移动端布局、双语文案、标签切换、面板高度稳定、折叠详情、键盘导航、手机滑动、六张截图及原图链接、剪贴板行为和控制台错误。运行截图用例核实所展示的操作。将首页覆盖到文档构建中，验证线上首页及保留的文档路由。静态页面不调用模型。
