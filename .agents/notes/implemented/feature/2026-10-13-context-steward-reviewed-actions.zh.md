# Agent Note: Context Steward 已审核操作

Status: implemented

[English](2026-10-13-context-steward-reviewed-actions.md) | 中文

## 问题

长对话可能需要一个分支中的证据，同时在另一个分支继续工作。只考虑来源的审核器无法表达这种区别，被动查看分支不能确定用户想继续的位置，而没有事件来源的偏好总结无法可靠检查或重置。每次审核都要求模型调用，也让确定性的 Context 操作产生不必要的费用。

## 决策

[Context Steward 指南](../../../../docs/user/guide/context-steward.zh.md)介绍基于原生 Session 图的统一审核流程。Local 为默认模式，不产生模型请求。显式 Fast 审核使用一次有界、无工具的请求，可分别提供目标分支与证据分数。明确的文本提示和原生图合法性约束建议。低置信度的新任务或含糊目标不能静默创建或选择分支。Fast 将准确的冻结系统提示、用户数据包、目标、provider/model 和 640-token 输出上限记录在原生 Session 日志中，不记录密钥；该记录用于审计，不训练偏好记忆，也不改变图修订。Deep 仍是隔离的 DSH 审核，`deepMaxRequests` 默认三次，可配置一至十次并计入重试；超时为 45 秒，每次输出上限为 1,200 tokens。每轮结束后的自动 Branch 分类需要主动开启。

Client 将 Move draft here 与 Locate 区分开。Move draft here 要求非空的未发送文本，是明确的目标分支操作；转移草稿时检查版本，并保护目标已有草稿。Host 仅在原生转移成功后记录手动路由证据。Locate 仍然只是查看，不贡献标签。分支生命周期建议与 Context 选择分开，需要单独确认。Local 只接纳明确生命周期提示；Fast 和 Deep 最多建议一次合法、非 no-op 的原生 Session 状态变化，明确提示优先。Complete 保留证据；之后的人工新轮次重新打开任务。

Policy memory 仍是可以从明确原生事件重建的投影。证据标明拥有它的 Session 与事件序号。重置记录各 Session 自有事件的水位，并保留原始对话与当前 Context Plan。重置后追加的事件，包括时间戳相同的事件，可以训练新投影。[Policy memory 决策](2026-10-12-context-steward-policy-memory.zh.md)负责估计与反馈规则。

## 考虑过的替代方案

**将证据相关性当作目标分支相关性。** 未采用，因为借用研究证据不应把正在进行的写作任务转移到研究分支。

**从被动 Locate 或卡片展示中学习。** 未采用，因为查看和展示不能表达预期的 Context 操作。

**仅凭时间戳重置，或删除选择记录。** 未采用，因为不同事件的时间戳可以相同，而删除记录会移除审计依据。

**调用额外的路由模型，或要求训练 reranker。** 未采用，因为 Fast 已负责语义审核请求，有界图数据包可以支持可替换 scorer，无需第二个 agent loop（智能体循环）或声称已经训练的 baseline。

## 影响

用户可以分别审核当前上下文、目标分支和任务状态，同时保留原生继承关系。确定性的 Local 建议没有审核 API 费用；含糊的词法输入仍有局限。语义分数是排序信号，不是校准后的概率。偏好规则展示支持度和事件证据，但不能证明真人个性化收益。

[无需密钥的回放](../../../../scripts/context-steward-replay.ts)从构造的 30 轮、4 Session 轨迹导出六个仅含历史信息的操作数据包。Fixture（测试前置数据）的预期结果保持分离；受控分数检查路由约束，而不是 scorer 准确率。原生投影必须保留六十个唯一聊天节点、已完成任务的证据与重入。配套 spec 检查历史不含未来决策，并检查独立运行产生相同数据包。组装后的 Web 验收测试单独负责 UI 到编译请求的证据。保存的模拟用户实验需要与简单条件 baseline 比较；工程回放不是 SOTA 证据。
