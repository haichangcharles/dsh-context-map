# Agent Note: Context Steward 已审核操作

Status: implemented

[English](2026-10-13-context-steward-reviewed-actions.md) | 中文

## 问题

长对话可能需要一个分支中的证据，同时在另一个分支继续工作。只考虑来源的审核器无法表达这种区别，被动查看分支不能确定用户想继续的位置，而没有事件来源的偏好总结无法可靠检查或重置。每次审核都要求模型调用，也让确定性的 Context 操作产生不必要的费用。

## 决策

[Context Steward 指南](../../../../docs/user/guide/context-steward.zh.md)介绍基于原生 Session 图的统一审核流程。Local 为默认模式，不产生模型请求。显式 Fast 审核使用一次有界、无工具的请求，可分别提供目标分支与证据分数。明确的文本提示和原生图合法性约束建议。低置信度的新任务或含糊目标不能静默创建或选择分支。Fast 在原生 Session 日志中记录准确且不含凭据的请求；当前聊天模型路径采用 640-token 文本输出上限，[Jev 路径](2026-10-15-personal-context-decision-cases.zh.md)则使用结构化问题；该记录用于审计，不训练偏好记忆，也不改变图修订。Deep 仍是隔离的 DSH 审核，`deepMaxRequests` 默认三次，可配置一至十次并计入重试；超时为 45 秒，每次输出上限为 1,200 tokens。每轮结束后的自动 Branch 分类需要主动开启。

Client 将 Move draft here 与 Locate 区分开。Move draft here 要求非空的未发送文本，是明确的目标分支操作；转移草稿时检查版本，并保护目标已有草稿。Host 仅在原生转移成功后记录手动路由证据。Locate 仍然只是查看，不贡献标签。分支生命周期建议与 Context 选择分开，需要单独确认。Local 只接纳明确生命周期提示；Fast 和 Deep 最多建议一次合法、非 no-op 的原生 Session 状态变化，明确提示优先。Complete 保留证据；之后的人工新轮次重新打开任务。

Policy memory 仍是可以从明确原生事件重建的投影。证据标明拥有它的 Session 与事件序号。重置记录各 Session 自有事件的水位，并保留原始对话与当前 Context Plan。重置后追加的事件，包括时间戳相同的事件，可以训练新投影。[Policy memory 决策](2026-10-12-context-steward-policy-memory.zh.md)负责估计与反馈规则。

当 Plan 刷新替换节点数据时，图保留 React Flow 的受控节点测量。搜索和 Locate 各自有明确的聚焦请求；每次请求只将已测量的目标适配到视口一次，无关节点的尺寸更新不会覆盖用户后续的平移。当前语言变化时，节点文案随之更新。[长对话浏览器检查](../../../../apps/web/tests/contextify-graph-refresh.e2e.ts)通过原生编译器验证 Plan 修改、Undo/Redo，以及借用可搜索的其他分支来源。

这些组件复用 DSH 的 Session、fork、持久化和编译器 API，React Flow 的节点与视口 API，以及 Dagre 布局。偏好归纳借鉴 [Mem0](https://arxiv.org/abs/2504.19413) 对证据和派生记忆的区分；本项目实现保存 Context 操作，而非一般个人事实。事件水位遵循[事件溯源投影模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)。这两项参考都没有引入第二个智能体运行时，也不能证明本项目优于其 benchmark。

控制器刷新内容未变时复用图和 Plan，不发出重复快照通知；比较仍保留同一图版本下的视图与推荐变化。消息控件只订阅自己的节点、模式和 pending 状态。Dagre 定位与选择、颜色更新分开缓存。在本机 Chromium 的同一负载（240 轮、120 个 delta、16 ms 回放间隔）中，三次采样的翻页中位耗时从 2,055.76 ms 降至 326.46 ms，Trajectory 从 953.96 ms 降至 160.40 ms，输入完成从 250.03 ms 降至 136.43 ms。三次输入均发生在回复结束前。原有预算与负载保持不变；这些本地回放结果排除了模型延迟，不能预测其他机器表现。控制器与消息控件的独立回归测试验证无变化刷新、同版本下的变化及原有操作。

浏览器集成保持 Map 改变宽度时的 Chat 阅读行为。贴底位置到达新的精确底部时，滚动状态先落定，再响应随后输入框或回复增长；离底阅读仍保留原采样阈值。轮次导航条追踪实测视口高度，在单轮对话增长出导航条时安装监听，并在隐藏后恢复可见时跟随当前轮次；普通阅读滚动和指针操作仍由用户控制。[Chat 滚动验收](../../../../apps/web/tests/chat-scroll-contract.e2e.ts) 的全部七条原有路径通过，未降低门槛，流式 fling 场景保持 Map 打开。原生对话 fixture 先观察 Map 自动打开，再通过真实 UI 恢复完整宽度参考面。子 Agent 执行详情路由不会自动打开不受支持的家族 Map。归档投影保留任务状态及其事件来源，即使归档 Session 属于另一家族也如此。审阅后的快照保留新增 Context 控件和 Event details，录制的模型日志和快照 normalizer 保持不变。React Flow 控件使用应用已有的表面与标签颜色别名和本地化标签；真实浏览器验证了浅色与深色主题中的图标对比度。

[线性 Context Map 布局决策](../bug-fix/2026-10-14-linear-context-map-layout.zh.md) 负责为首次打开延迟增加的单链精确定位；上述控制器缓存与已审阅操作决策继续有效。

## 考虑过的替代方案

**将证据相关性当作目标分支相关性。** 未采用，因为借用研究证据不应把正在进行的写作任务转移到研究分支。

**从被动 Locate 或卡片展示中学习。** 未采用，因为查看和展示不能表达预期的 Context 操作。

**仅凭时间戳重置，或删除选择记录。** 未采用，因为不同事件的时间戳可以相同，而删除记录会移除审计依据。

**调用额外的路由模型，或要求训练 reranker。** 未采用，因为 Fast 已负责语义审核请求，有界图数据包可以支持可替换 scorer，无需第二个 agent loop（智能体循环）或声称已经训练的 baseline。

## 影响

用户可以分别审核当前上下文、目标分支和任务状态，同时保留原生继承关系。确定性的 Local 建议没有审核 API 费用；含糊的词法输入仍有局限。语义分数是排序信号，不是校准后的概率。偏好规则展示支持度和事件证据，但不能证明真人个性化收益。

[无需密钥的回放](../../../../scripts/context-steward-replay.ts)从构造的 30 轮、4 Session 轨迹导出六个仅含历史信息的操作数据包。Fixture（测试前置数据）的预期结果保持分离；受控分数检查路由约束，而不是 scorer 准确率。原生投影必须保留六十个唯一聊天节点、已完成任务的证据与重入。配套 spec 检查历史不含未来决策，并检查独立运行产生相同数据包。组装后的 Web 验收测试单独负责 UI 到编译请求的证据。保存的模拟用户实验需要与简单条件 baseline 比较；工程回放不是 SOTA 证据。
