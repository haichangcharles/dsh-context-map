# Agent Note：个性化 Context 校准

状态：已实现

[English](2026-10-09-personal-context-calibration.md) | 中文

## 问题

Context Map 已有明确的 Include/Exclude 与 Keep/Move 操作，但此前所有 Session family 都采用相同的候选排名和 Branch 阈值。重复提出已被拒绝的 Branch 建议，或漏掉与此前手动纳入相似的材料，都会增加用户操作。现有日志的真实 UI 选择仍不足以测量效果。

## 决策

Branch review 把 Client 声明的 Keep/Move 事件与持久化建议关联，每条事件只在所属 Session 计数一次，并按事件时间保留最近 32 条，随后在通用建议阈值上下最多调整五个置信度百分点。明确 Keep 与 Move 现在产生对称的相反更新，避免用户接受高置信 Move 后因减去模型置信度而几乎学不动。两个伪样本限制稀疏反馈的影响；候选措辞和 branch 深度为过往选择赋权。在相近 branch 深度至少有五次已审核选择后，采用 Beta 先验平滑的风格比例：以 Keep 为主可抑制非极端置信度的通用 Move，以 Move 为主可把非极端置信度的通用 Keep 转成待确认卡。另有词项相近 Move 处理低置信通用 Keep。所有搬迁仍需用户批准。用户仍须授权搬迁，建议本身不是准确率证据。

Fast Context 推荐使用按事件时间排序的最近 32 条经 Client 确认的 Include/Exclude 选择：确实改变结果且只涉及单个节点的直接编辑，以及已接受建议中的选择。直接恢复到 `natural` 且确实改变结果时，系统按图位置解释反馈：活动路径恢复是正向 Include，跨分支恢复是负向 Exclude；无变化的直接操作不计入。一次接受的批量建议在所选节点间总权重为一，即使应用后 plan 没有变化也计入。每条选择以此前最近一条用户消息近似当时目标，读取所选节点的稳定图预览，并记录该节点是否位于当时的 Session 路径，避免后来的 Archive overlay 改写旧样本。Fast 路由与个人残差共用规范化词项及中文双字片段匹配，让连续中文句子保有局部词项重合。局部词项残差和至少四次同图位置加权观察后启用的组织风格项经过两个伪样本收缩，上限为 0.2，在有界模型 review 之前重排跨分支候选。普通校验通过后，它抑制与历史编辑强烈冲突的 Include/Exclude 动作，还可从有词项相关性或匹配既往 Include 的图路由跨分支候选新增最多两条正向 Include 建议；结果再次校验。显式 override 仍强制保留。Deep 推荐不变。两种策略都不增加模型调用。

随后对稀疏反馈的审查发现：要求每个“来源类型×路径位置”分格内各有四次观察，会让只有十次编辑的模拟用户几乎得不到个性化。Fast review 现另用至少五条带类型的选择，按过往反馈的留一准确率，在来源类型、活动路径和联合分格三个专家之间选一个。匹配观察至少三次且 Beta 平滑比例形成强偏好时，它可阻止相反的通用动作，或提出最多两条活动路径 Exclude 供用户确认。满足[来源绑定 Web 导入决策](2026-10-10-source-bound-web-import.zh.md)的跨分支 Web 结果也可获得有界 Include 建议；worker 证据仍不可导入。原图校验和用户确认保持不变。在已暴露的模拟卡上，改动前产品校准器在两种假定路径映射下都与通用建议同为 9/20；改动后若所有可选来源都算 off-path，为 12/20；只有把研究者写的 `resume` 标签**假定**为活动路径成员时才到 17/20。两种映射都不是观察到的原生 Session 图，因此只是开发诊断，不是留出产品准确率。

图将原生 Web 观察和 worker 回报记录为带类型的证据。合格 Web 节点还保留匹配工具调用是 `web_search` 还是 `web_fetch`；已确认选择与推荐 packet 会保留这一动作。来源及联合偏好专家在动作存在时区分两者，旧版缺少细分动作的 Web 选择回退到宽泛 `web` 类型。活动路径上的证据可 Exclude；具备来源绑定的兄弟分支 Web 证据可作为已记录的 recall snapshot Include；跨分支 worker 导入与证据 Archive 仍不可用。这避免多次排除搜索结果被泛化成丢弃已访问页面或聊天历史的偏好。来源绑定的委派仅在原生 Web 结果的前驱是匹配的 Web 工具调用时接受它。来源声明仍以没有未记录的环境输入和外部读取为前提。

`uiOrigin` 由 Client 声明，也可能被其他 Remote 调用方伪造；它不能证明人类身份或建议曝光。节点目标由 Session 日志推断，而非编辑时直接记录。无变化或批量直接编辑，以及已生成但未决定的建议都不作为训练样本。接受建议是一种明确的已审核选择，但也不能证明建议曝光或用户满意。

## 考虑过的替代方案

- **现在训练 reranker 或 LoRA** — 暂缓，因为现有日志缺少足量直接选择标签；训练模型既增加成本，也没有可信目标。
- **把全部历史放入个性化 prompt** — 首版拒绝，因为它会增加上下文，并模糊究竟是哪次编辑改变了决策。
- **使用不受约束的用户专属阈值** — 拒绝，因为一次误点击就可能让未来 Branch 建议消失或泛滥。

## 结果

已发布路径有两个有界、无需训练的适应点，可以在相同模型调用下与通用基线比较。定向测试证明了阈值抑制、通用分类器低置信 Keep 但多次相近 Move 后出现确认卡、原本被截断的跨分支候选重新进入列表、冲突 Context 建议被过滤、经过图路由的 Include 建议，以及从原生已审核选择中恢复 Web 工具动作。这些都是受控测试样例，不是人类结果改善的证据。另一次留出 AI 用户特征审计把构造的 `resume/new` 映射成原生活动路径关系：保留 Web 工具动作后，“按来源整理”的角色从十次弃答变为 10/10 预测，“按路径整理”的角色仍为 10/10。这只检验特征信息保留，不是产品任务成功率：关系映射是假定的，测试卡片并非原生 Plan 执行，简单条件表也与方法打平。论文仍需可执行的 Session 选择和 Web 任务结果，才能宣称个性化收益。

后续原生 Session 回放暴露两个 Fast 路由问题：推荐文本漏掉 Web 工具结果正文，只按偏好分排序新增候选会把其他分支排到当前任务之前。带原生调用来源的 Web 候选现包含调用参数和观察文本；自动跨分支 Web Include 比聊天 Include 要求更强的任务词项重叠，新增候选按词项相关性与个人残差之和排序。由于这些修改是在检查 20 条 AI 用户案例后作出的，这批案例已成为开发数据。通用推荐恒返空建议的 mock 条件下，原生提案接受与编译匹配全部 20 条模拟可选来源选择，其中三条形成 Web recall snapshot；这只能检验执行，不能算独立效果估计。论文仍需未触碰的任务集和 Web 下游结果。
