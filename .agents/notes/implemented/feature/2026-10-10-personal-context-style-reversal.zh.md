# Agent Note：个性化 Context 风格反转

Status: implemented

[English](2026-10-10-personal-context-style-reversal.md) | 中文

## Problem

原有免训练 Context 建议器从最多 32 次已确认选择估计稳定偏好。同一 Web 来源分格先有八次 Include 时，随后三次相反的 Exclude 会让它弃答，但要到约二十次 Exclude 才明确建议 Exclude。用户已多次纠正，改变后的组织习惯却迟迟得不到辅助。

## Decision

在选择来源、路径或联合分格专家之前，建议器检查来源类型、Web 动作和活动路径位置完全相同的单条权重选择。只有至少五次较早选择经 Beta 平滑后形成强烈的相反多数，且该分格最近五次选择一致支持新动作，才切换建议。一次接受多节点建议时产生的分数权重选择不能算作完整确认。原有最多 32 条选择的界限和图校验器仍生效。此规则只改变待审核建议；Plan 编辑仍需用户确认。

有界 Exclude 阶段现在只考虑活动路径上当前仍被包含的候选。此前，已经 Exclude 的节点可能占掉两个建议名额，随后被图校验器当作无效重复操作丢弃，导致真正仍被包含的来源拿不到有用的 Exclude 建议。

## Alternatives considered

- **始终使用全部历史的多数直到旧选择被淘汰** — 拒绝，因为八次旧 Include 后需要约二十次新 Exclude 才能切换建议。
- **最近一次选择立即决定风格** — 拒绝，因为一次误操作或特定任务选择可能推翻稳定习惯。
- **训练时序模型** — 暂缓，因为现有 Context 选择日志没有足够的已观察偏好变化来识别参数或验证下游收益。

## Consequences

受控案例从八次 Include 转向 Exclude 时，第五次纠正即可切换建议；四次不会，其他 Web 动作或批量反馈中的分数权重也不会继承该反转。既有 Persona2Web 衍生原生留出回放的编译来源选择逐项不变，仍为 19/20。这些是实现检查，不能证明真实用户按此速度改变偏好，也不能证明检测器改善 Web 任务成功率。固定阈值在纵向选择足以校准之前只是保守的产品规则。

原生 Session family 测试还确认，五次经过审核的 Web 反转之后，新 Web 结果会收到有效的 Exclude 建议，接受建议会让该结果从下一次编译请求中消失。已排除的来源不再占用有限的 Exclude 名额。
