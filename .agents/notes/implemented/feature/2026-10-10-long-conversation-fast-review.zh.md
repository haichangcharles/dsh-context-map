# Agent Note：长对话 Fast 审核候选

状态：已实现

[English](2026-10-10-long-conversation-fast-review.md) | 中文

## 问题

Fast 审核此前只把活动路径最近三轮、分支支点、显式覆盖和跨分支候选交给 Agent。长对话早期的约束仍会进入模型请求，但用户回到该话题时，审核 Agent 可能看不到它。用户只能自行找到并排除该消息，或运行成本更高的 Deep 审核。

## 决定

Fast 路由现在按与最新目标的词项重叠，对活动路径上较早但仍被包含的消息排序。对排名靠前的旧消息，它还寻找位置更晚、角色相同且与该旧消息词项重叠至少 0.2 的活动消息；即使后来的纠正改写了当前目标用词，两者也可能一同进入审核。最多接纳八条远处活动消息，同时保留原有必选节点，并在 32 节点 packet 内为跨分支候选预留最多十二个位置。与目标零重叠的消息只能作为相关旧消息的后续配对进入。Packet 保留原有图连接和活动路径身份；路由不会修改持久 Context Plan。审核结果仍须经过原有校验和用户 Apply。

跨分支名额先为每条非活动分支保留一个来源：其最高候选分数需达到跨分支最高分的 40%，且至少为 0.05；余下名额沿用原有分数顺序。这借鉴推荐系统的候选多样性，同时保持 32 节点上限，也不把同一分支的重复消息当成多个独立话题。来源合法性、用户 Exclude 与 classifier 的最终选择不因此改变。

Fast 审核只接受本次请求的 Include 和 Exclude 建议。提示词要求模型把 Archive 留空；即使模型仍返回 Archive，校验器也会移除这些建议。Profile 持有的 Archive 指引用于 Deep 审核，后者保留需逐项确认的 Archive 建议。原有结构检查仍会拒绝无效节点 ID，以及对 Web 或 worker 证据的 Archive 尝试。

## 考虑过的替代方案

**每次旧约束都运行 Deep review。** 这会让常见长对话路径承担较慢的整树检查，而 Fast 仍无法处理常见的纠正案例。

**只凭图中的时间排除较早活动消息。** 暂缓任务和后来被更正的证据仍可能有用，因此路由器只把候选交给审核。

**所有跨分支名额都按分数填满。** 匹配词项重复出现的长分支会完全遮住另一条相关度稍低的非活动分支，因此有界候选包先保证达到门槛的其他分支可见。

**让 Fast 根据有界候选包建议持久 Archive。** 一条暂时无关的分支未必已经过时。在固定的 Web 长对话候选包上，仅澄清一句提示词后，模型仍漏掉本轮需要的 Exclude，却为暂时无关的节点提出十二条 Archive。只修改提示词无法保证生命周期动作与本轮选择分开。

## 后果

有界单测检查四十节点的活动历史：旧屏幕约束和较新的纠正都能与最近轮次、跨分支节点一同进入 Fast 审核。Loader 组合的浏览器回放使用三十轮 Chat 历史：用户在旧话题开分支，手动排除过时预算；旧屏幕约束与用词不同的后续纠正同时进入 Fast 审核后，用户从固定的无密钥 classifier 回复中接受排除旧屏幕约束，同时明确保留当前纠正。每次编辑都改变下一次实际模型请求，岔路话题保持在活动分支之外。这验证的是审核管道，并不能证明真实模型会选对过时约束，或个人策略提升了准确率。较长文本、改写表达和无关词项匹配仍可能造成检索失误。

零 API 策略检查发现：五次排除活动路径中的过时聊天消息后，旧风格规则会同时建议排除旧约束和后来的更正。Fast 向 classifier 展示最多四条有界的、经确认的加权选择，包括完整多项审核中显式保留当前的选择；确定性的风格层不再仅凭来源／路径计数新增活动聊天 Exclude。模型仍可提出具体聊天排除供用户审核，Web 和 worker 证据继续保留按来源类型的建议。浏览器回放检查已确认的预算编辑确实进入模型可见的 Fast packet；它不衡量真实模型是否学会偏好。

已接受的多节点 Context 建议现在还能贡献最多两条成组案例，每组不超过四个选择。组合中的 Include/Exclude 关系会一起保留，不把有分数权重的批量选择伪装成数条独立、完整权重的偏好。每个选择还记录确认前后的纳入状态；若组内有任何节点没有改变，就舍弃整组案例。只有带 Client 标记、确实改变计划且记录完整的已审核建议才合格；案例只进入有界模型输入，不直接改变确定性 Plan，也不能证明已学到偏好。单测检查跨继承 Session 前缀的提取与 Fast packet 上限。

已确认的建议选择会保存审核时使用的有界目标。发送前审核的草稿尚无对应的 `user/message`；若与最近一条已记录用户消息配对，偏好案例和成组计划案例会被错误标注。确认事件携带该目标，未审核的建议不生成偏好证据。旧事件仍使用已记录轮次作为兼容回退。针对性测试覆盖仅存在于草稿中的“保持当前”审核和已接受的成组计划案例。

一个构造的同级分支案例检查：某条分支有十六条高度匹配的消息时，另一条分支中度匹配的来源仍能进入候选包。这只验证单个样例的候选可见性，不证明自然长对话中的 Context 选择质量或回答准确率。

单测检查同时包含 Exclude 和 Archive 的 Fast 输出会保留 Exclude、清空 Archive，而 Deep 会保留结构合法且需确认的 Archive 建议。这可阻止已观察到的 Fast 误分类进入其审核卡片，但不证明 Deep 能正确判断节点是否过时。
