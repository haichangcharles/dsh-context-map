# Agent Note：完整 Context 策略确认依据

Status: implemented

[English](2026-10-20-complete-context-policy-evidence.md) | 中文

## 问题

接受单条 Context 修改不能识别用户对任务自有或任务加祖先完整保留策略的偏好。路由确认可能仅移动草稿。模型解析出的策略不是用户确认，既有 Client 也可能忽略新展示字段，同时仍提交普通确认。

## 决策

[Contextify](../../../../packages/context/contextify/README.zh.md)在最终待审核建议上附加可选的服务端保留策略描述符。Jev 返回后重新计算标准原生基础范围，借用或删除来源的例外不能获得纯策略标签。空范围、不可核验的祖先、替换来源，以及自有/祖先集合相同的情况均省略描述符。携带 Context 时保留描述符的原始归属，以及任务或新任务父节点身份。

服务端拥有的发布身份将展示 key 绑定到准确的待审核建议、原始修订和完整来源集。Client 显示策略，并仅在明确完整 Apply 或完整 Carry 时回显 key。缺失、错误或旧 key 保留普通操作行为，但不产生新策略标签。key 不提供权限，也不证明真人身份或注意力。仅路由确认、局部 Keep 选择、无标记调用、关闭个性化和未改变的 Plan 均不标注。

现有修订、手动约束和来源检查后，Host 比较实际应用的原生集合与完整建议集合。匹配且发生改变的确认会在既有选材审核事件上附加标注，不建立独立记忆存储或操作所有者。相邻的自有 node-choice 和原生 Plan 状态提供 Undo/Redo 依据，现有 Profile 水位排除重置之前的证据。继承副本、格式错误的确认和含义不明确的旧历史均不增加样例。

已启用的 Host 动作/目标数据包和可检查决策快照最多携带四条完整策略样例，各自包含拥有它的 Session/事件、时间、策略、归属与最多200个 Unicode 码点的目标。当前显式保留指令优先；只有明确适用的历史目标才能支持完整保留，冲突或无法判断适用性时弃权，单次接受不代表一般偏好。缺失或空样例列表保持普通目标请求不变。历史归属不授权当前目的地，也不进入回答 Context。现有排序加分、阈值、路由默认值与推理次数均不改变。

## 考虑过的替代方案

**从局部选材集合推断策略。** 不采用，因为例外、相同来源集和手动约束会使解释无法识别。

**没有展示确认就信任建议描述符或 Client 来源标记。** 不采用，因为旧 Client 可在未展示新策略时接受同一来源集。不包含发布身份的 key 还允许旧审核单为新目标标注。

**另建 persona 存储或从无变化确认学习。** 不采用，因为原生事件已经拥有证据，而未改变范围不具备此投影沿用的同一可撤销 Plan 变更。

## 影响

产品可以将可识别的完整范围选择与局部修改样例分开保留。工程替身验证旧调用兼容、例外、精确待审核身份、完整原生范围、Carry、有界模型输入、Undo/Redo、重置和关闭个性化。这些只验证学习输入链路，不证明真实用户模型准确率、自动 Branch 质量或模型/回答改善。新任务空范围与未改变的范围仍不进入该投影。
