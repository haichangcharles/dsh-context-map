# Agent Note：逐项 Context 审核反馈

Status: implemented

[English](2026-10-10-selective-context-review.md) | 中文

## 问题

整单接受或关闭的建议面板无法表达“移除旧的 Chat 约束，但保留附近的当前约束”。若把未接受的整单视为负反馈，还会把沉默与明确的 Context 偏好混淆。

## 决策

每项拟议的 Context 改动都有“保留当前”控件。Client 根据待审建议及图修订，提交准确的接受动作和拒绝节点 ID。Host 拒绝不属于该建议或重复的拒绝项，核对接受动作恰好等于建议中剩余的动作，再以一条 \`contextify/recommendation-reviewed\` 事件记录完整建议以及接受／拒绝划分。全部拒绝只记录选择，不增加 Plan 修订；部分接受只提交接受的改动。关闭面板时可在关闭事件中保留用户此前切换的节点 ID，但关闭记录不用于偏好学习。

Fast review 从 Session family 中恢复 Client 声明的已确认审核选择。接受项保留建议动作；拒绝 Include 表示继续 Exclude，拒绝 Exclude 表示继续 Include。一张审核单的全部条目合计权重为一。有界 Fast 数据包保留分数权重，让分类器看到已审核示例，确定性的个人残差也消费它们。旧的已接受 \`node-choice\` 事件仍可读取；新的审核事件避免重复计算相邻的 \`node-choice\`。

## 考虑过的替代方案

**整单应用或关闭。** 一项建议错误时会连同有用项一起失去，也无法获得逐项纠正信号。

**把关闭面板中的每项都当成负标签。** 关闭可能只是推迟决定，因此个人策略只从已确认的审核中学习。

## 后果

用户可以纠正建议中的错误项，同时保留有用项；下一次 Fast review 可压制与显式“保留当前”选择冲突的重复建议。Plan 仍是权威状态，确认前的建议不会改变下一次模型请求。这些事件描述 Client 路径，并不证明已认证的人类身份；本地行为测试与 30 轮浏览器回放证明机制，而非人群层面的个性化收益。
