# Agent Note：逐项 Context 审核反馈

Status: implemented

[English](2026-10-10-selective-context-review.md) | 中文

## 问题

整单接受或关闭的建议面板无法表达“移除旧的 Chat 约束，但保留附近的当前约束”。若把未接受的整单视为负反馈，还会把沉默与明确的 Context 偏好混淆。

## 决策

每项拟议的 Context 改动都有“保留当前”控件。Client 根据待审建议及图修订，提交准确的接受动作和拒绝节点 ID。Host 拒绝不属于该建议或重复的拒绝项，核对接受动作恰好等于建议中剩余的动作，再以一条 `contextify/recommendation-reviewed` 事件记录完整建议以及接受／拒绝划分。全部拒绝只记录选择，不增加 Plan 修订；部分接受只提交接受的改动。关闭面板时，`contextify/recommendation-dismissed` 保留明确拒绝的节点 ID 与有界审核目标；只有这些条目提供拒绝证据，未决定的条目没有标签。

Fast review 从 Session family 中恢复 Client 声明的已确认审核选择。接受项保留建议动作。拒绝 Include 或 Exclude 只表示拒绝这项改动，不会制造相反动作的正向标签。策略估计读取 Apply 和关闭时的明确拒绝；同一草稿的重复建议过滤器只压制对应的动作与节点。每个有标签条目的权重为审核单总条目数的倒数，因此部分关闭反馈合计至多一条有效观测。风格记忆排序器和模型可见案例只使用正向编辑。旧的已接受 `node-choice` 事件仍可读取；审核事件避免重复计算相邻的 `node-choice`。

## 考虑过的替代方案

**整单应用或关闭。** 一项建议错误时会连同有用项一起失去，也无法获得逐项纠正信号。

**把关闭面板中的每项都当成负标签。** 关闭可能只是推迟决定，因此只有明确标记“保留当前”的条目提供拒绝证据。

## 后果

用户可以纠正建议中的错误项，同时保留有用项；下一次 Fast review 可压制与显式“保留当前”选择冲突的重复建议。Plan 仍是权威状态，确认前的建议不会改变下一次模型请求。这些事件描述 Client 路径，并不证明已认证的人类身份；本地行为测试与 30 轮浏览器回放证明机制，而非人群层面的个性化收益。
